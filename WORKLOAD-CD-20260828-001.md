1. Study Objective

This study is the first empirical calibration workload for the Compression Dividend Benchmark.

The purpose is not to demonstrate that Governed State Reuse wins.

The purpose is to measure, from real observations, the economic difference between:

Path 1 — Pure Recomputation

Path 2 — Provider Prompt Caching

Path 3 — Governed State Reuse

for one narrow, repeatable, quality-equivalent task.

The study asks:

For a requesting AI or agent that needs a specific canonical structured result, is it less expensive to reconstruct that result through model inference, use provider prompt caching, or retrieve a validated governed state directly?

2. Economic Perspective Boundary

This study uses the requesting-agent perspective.

All costs represent costs incurred by the agent or application attempting to obtain the required result.

This distinction is mandatory.

For this study:

A payment made to a governed-state endpoint is a cost to the requesting agent.

That payment may be revenue to the infrastructure operator, but operator revenue is outside this study's accounting boundary.

Cloudflare infrastructure expense, server cost, and repository-owner operating margin are not counted as requester costs unless directly charged to the requester.

A future study may separately examine the infrastructure-operator perspective.

Requester-side and operator-side economics must not be mixed in the same Compression Dividend calculation.

8. Path 1 — Pure Recomputation

Path 1 represents fresh logical reconstruction.

No previously computed task-specific answer may substitute for the requested result.

The model may receive the raw authoritative source material necessary to answer the task.

The purpose is to measure the economic cost of reconstructing the required structured result from source information.

Recommended control design:

Provide the model with the authoritative raw source or equivalent source context.

Provide the frozen task instructions.

Require the model to construct the declared Study 001 output schema.

14. Path 3 Cost Decomposition

The requester-side Path 3 cost should be decomposed where practical into:

Cpayment

Direct amount paid to the governed-state service.

Cr_requester

Any additional requester-side retrieval or transport cost not already represented by Cpayment.

Cv_requester

Any requester-side verification cost.

Cp_requester

Any requester-side provenance, authority, rights, or policy-validation cost.

Cm_requester

Any eligible variable per-successful-hit state-service cost incurred by the requester and not already included in Cpayment.

Cresidual

Any remaining fresh model inference or compute required after the governed state is accepted.

Avoid double-counting.

If Cpayment already purchases retrieval, validation, provenance, and delivery as one bundled service, do not arbitrarily recreate those same costs as separate requester charges.

Instead record:

Cpayment = measured bundled service charge

and set separately unobserved requester components to zero unless they genuinely occur outside the paid service.

17. Governed-State Hit Definition

A governed-state attempt counts as a hit only when:

The state is successfully retrieved.

The correct canonical record is returned.

The state passes the declared verification criteria.

The state passes the Study 001 quality-equivalence gate.

The state is accepted for use by the requesting workflow.

A network 200 response alone is not a hit.

A candidate result that is rejected for incorrect identity, stale state, incomplete fields, rights failure, or quality failure is not a hit.

19. Economic Substitution Fraction

Economic Substitution Fraction is the key paired-control measurement in Study 001.

For every accepted governed-state hit:

Measure the equivalent fresh-control recomputation cost.

Call this:

Cre_control

Then measure any residual fresh model computation still required after the governed state is accepted.

Call this:

Cresidual

Calculate:

s = 1 − Cresidual / Cre_control

If no further model inference is required after governed-state retrieval:

Cresidual = 0

and:

s = 1

If the governed state only reduces part of the required model execution:

0 < s < 1

If the state does not reduce fresh-computation cost:

s = 0

20. Important Interpretation of s

Study 001 must not estimate s from semantic similarity.

Do not derive s from:

Token overlap

Embedding similarity

Cosine similarity

Graph similarity

Answer similarity

Percentage of fields already present

Percentage of context reused

Cache-hit rate

Reasoning-step estimates

unless those measurements are explicitly translated into directly avoided economic cost.

s is a cost-weighted substitution metric.

The economic measurement is primary.

37. Maximum Economically Viable Governed Price

After measuring all non-price requester-side Path 3 costs, calculate the maximum governed-state retrieval price that would preserve:

Dincremental = 0

This produces a useful economic ceiling:

Pmax_governed

Interpretation:

If actual governed retrieval price is below Pmax_governed, the requesting agent has room for a positive Incremental Compression Dividend.

If actual governed retrieval price equals Pmax_governed, the requester is at economic neutrality.

If actual governed retrieval price exceeds Pmax_governed, the requester is economically better served by the best measured competing path.

This is a derived pricing metric.

It must not be used to retroactively alter observed results.

39. Separation From Seller Economics

Requester-side Compression Dividend is not the same as operator profit.

For example:

Requester may save $0.050 through governed reuse.

Requester may pay $0.005 for the governed result.

Operator may incur $0.001 in infrastructure expense.

These represent different quantities.

Study 001 measures requester-side Compression Dividend.

A later operator-economics study may calculate:

Revenue

Variable infrastructure cost

Contribution margin

Setup amortization

and seller-side economics.

Do not merge those concepts in Study 001.
